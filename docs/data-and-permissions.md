# データと権限

[READMEへ戻る](../README.md)

現在のファイル配置は[構成と処理の流れ](architecture.md)を参照してください。ソースへのリンクは、この文書と同じ版の実装を指します。

この文書は `v2026.10.31.3` の保存・通信・権限の扱いを説明しています。コードで確認した保存・通信の仕組みと、OSやブラウザーに委ねる動作を分けて記載しています。

## 保存される場所

| データ | 保存先と用途 |
| --- | --- |
| 撮影した写真・動画、作成したPDF、サムネイル | ブラウザーのIndexedDB。履歴からの表示・保存・共有に使います。 |
| 録画途中のデータと録画セッションの状態 | 同じIndexedDB。保存に成功した断片を、停止後の確定処理や中断録画の復元に使います。 |
| 撮影設定と選択したカメラの識別子 | ブラウザーのlocalStorage。次回起動時の設定復元に使います。手動で選んだマイクOFFも保存し、動画への切り替え時にONへ戻さないようにします。 |
| アプリ画面を構成するファイル | Service Workerのキャッシュ。取得済みの画面資材をオフラインで開くために使います。撮影履歴とは別の保存領域です。 |

撮影直後の「保存」は、ブラウザー内の履歴へ記録する処理です。端末の写真アプリや任意のフォルダーへ自動で追加されるわけではありません。大切なデータは履歴から「端末に保存」または「共有」を使い、保存先で実際に開けることを確認してください。

ブラウザー内の履歴は、利用中のブラウザー・プロファイルにおけるこのサイトの保存領域に属します。別のブラウザーや別端末への同期機能は実装していません。サイトデータの消去やブラウザーの容量整理によって失われる場合があります。永続保存の許可を要求する処理はありますが、許可やデータの保持を保証するものではありません。

## 保存領域のアクセス境界

IndexedDBとlocalStorageのアクセス境界は、プロトコル・ホスト名・ポートで決まるオリジンです。この公開版では `https://tomoponz.github.io` となり、`/quiet-camera/` というパスだけでは隔離されません。同じオリジンで動く別のGitHub Pagesプロジェクトのスクリプトからも、撮影データや設定へアクセスできます。別サイトとの自動同期処理を実装しているという意味ではなく、ブラウザーのアクセス制御の単位を説明しています。

今回の修正では、既存データを引き続き利用できるよう、公開URL・DB名・DBの版・設定キーを維持しています。別オリジンへ移す場合は、既存データを取り出して移行する手順を別途用意する必要があります。仕組みは[MDNのIndexedDBの説明](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Basic_Terminology)を参照してください。

## 通信と共有

確認したアプリコードには、撮影した写真・動画・音声を運営者へ自動アップロードする処理はありません。広告SDK、アクセス解析SDK、ログイン機能、クラウド保存機能も組み込まれていません。

一方、アプリ本体や更新ファイルの取得時には配信元であるGitHub Pagesと通信します。Service Workerも、同じ配信元へのGETリクエストをネットワーク優先で送り、失敗した場合にキャッシュを使います。そのため、アプリ全体が「一切通信しない」わけではありません。配信元への通常のWebアクセスと、撮影データの自動アップロードは別のものです。

「共有」は、利用者が選んだファイルをOS・ブラウザーの共有機能へ渡す操作です。共有先として選択したアプリがネットワーク送信やクラウド保存を行う場合があります。「端末に保存」の保存先、通知、写真アプリへの追加方法もOSとブラウザーに依存します。アプリ内の「保存を開始しました」という表示はダウンロード処理の開始を示すものであり、保存先への書き込み完了を保証するものではありません。

## 削除で消えるもの

- 履歴の「削除」は、確認後にアプリ内の該当記録を消去します。関連する録画断片（チャンク）は、ほかの履歴項目から参照されなくなった時点で解放します。
- 履歴から削除しても、すでにダウンロードしたファイルや共有先に渡したコピーは消えません。それぞれの保存先で管理してください。
- 復元待ちの録画一時データは、履歴の復元案内から操作します。「一時データを保存」は再生未確認のデータを取り出す操作であり、元の一時データを自動で消去するものではありません。
- ブラウザーのサイトデータ消去では、選んだ消去対象によって履歴、録画一時データ、設定も失われる場合があります。アプリには消去後の履歴をごみ箱やクラウドから戻す機能はありません。

## カメラとマイクの権限

| 権限・機能 | いつ使うか | 利用できない場合 |
| --- | --- | --- |
| カメラ | 「カメラを許可」や「動画」への切り替えで映像を取得するとき | 起動できなければ撮影ボタンを無効にします。カメラだけを要求して拒否された場合は、設定方法と「もう一度試す」を案内します。 |
| マイク | 初めて動画へ切り替えるとき、動画モードでカメラを起動するとき、または設定をONにするとき。手動OFFや同じ画面での拒否後は自動要求しません | MIC OFF・「音声なし」を表示し、独自の確認ダイアログは出しません。直前にカメラ映像を取得できていた場合は音声なしで接続し直し、未取得なら明示的な再操作を待ちます。 |
| 位置情報 | 要求する処理はありません | — |
| 永続保存 | 対応ブラウザーで保存領域の保持を要求するとき | 許可されなければ通常のブラウザー管理下で保存します。 |
| 画面の点灯維持 | 対応環境でカメラ利用中に要求するとき | 失敗してもカメラ処理を続けます。画面の点灯を保証しません。 |

ページを開いただけではカメラやマイクを取得しません。動画へ切り替えたときにマイクを準備し、録画ボタンを押したときに改めて確認を重ねることはしません。すでに許可されている場合にブラウザーの確認が省略されるか、OS側の確認も必要かは利用環境によります。Webサイト側から権限設定を勝手に変更することはできません。

マイクの許可を拒否した後は、再読み込みするまではモードを往復しても再要求しません。再試行したい場合は必要に応じてOS・ブラウザーの権限設定を変更し、アプリのマイク設定をONにしてください。手動で選んだOFFは再読み込み後も維持され、ONを選ぶと解除されます。従来の版が常に保存していたOFF値は、利用者が明示的に選んだOFFとは区別します。

撮影時のマイクをOFFにしていても、過去に音声付きで保存した動画を履歴から再生すれば音が出ることがあります。画面のMIC表示は撮影時の録音設定を示すものであり、端末全体の消音設定ではありません。
